# Kinder Edu 섹션별 페이지 기획 인계서

> 프로젝트: 지니쌤의 킨더에듀 (`kinder-edu`)  
> 문서 목적: 일반 채팅에서 섹션별 페이지의 기획 방향을 논의하기 위한 현행 홈페이지 요약  
> 기준 상태: Alpha Version 1 이후 메인 홈페이지 구현본  
> 작성일: 2026-09-26

---

## 1. 이 문서를 채팅에서 사용하는 방법

이 문서를 일반 채팅에 첨부하고 다음과 같이 요청한다.

```text
첨부한 SECTION_PAGE_PLANNING_HANDOFF.md를 먼저 읽어줘.
현재 메인 홈페이지의 프레임 규격, UI 스타일, 섹션 순서, 인터랙션,
이미지 제작 규칙은 유지하면서 6개 섹션별 페이지의 기획 방향을 정하고 싶어.

바로 화면을 만들지는 말고 먼저 아래 순서로 논의해줘.
1. 전체 섹션 페이지에 공통으로 적용할 프레임과 내비게이션
2. 각 섹션의 목적과 핵심 사용자 행동
3. 각 섹션의 첫 화면 정보 구조
4. 데스크톱·태블릿·모바일 레이아웃
5. 필요한 콘텐츠와 이미지 목록
6. 구현 우선순위

확정된 내용과 미확정 내용을 구분하고, 임의로 기능이나 콘텐츠를 추가하지 마.
```

## 2. 서비스와 사용자

- 브랜드명: **JINNI'S / 지니쌤의 킨더에듀**
- 주요 사용자: 30~40대 유치원·어린이집 교사
- 전체 방향: 교육 플랫폼의 실용성 + 에디토리얼 구성 + 웹툰 캐릭터 IP
- 정보 밀도: 낮게 유지하고, 중요한 콘텐츠와 행동을 먼저 보여준다.
- 이미지에 제목과 설명을 합성하지 않는다. 제목·본문·버튼은 HTML 텍스트로 구현한다.
- 기존 메인 캐릭터와 각 섹션 캐릭터 원본 이미지는 임의로 크롭·확대·변형하지 않는다.

## 4. 기준 프레임 규격

### 4.1 데스크톱 기준 좌표계

- 기준 브라우저 뷰포트: **`1680 × 940px`**
- 앱 프레임: **`1600 × 870px`**
- 뷰포트 바깥 여백:
  - 왼쪽 `40px`
  - 오른쪽 `40px`
  - 위 `30px`
  - 아래 `40px`
- 앱 프레임 비율: **`1600 / 870 = 1.8391:1`**
- 앱 프레임 바깥 라운드: **`26px`**
- 데스크톱 앱 너비: `min(100%, 170.213vh)`
- 메인 프레임은 `aspect-ratio: 1600 / 870`을 유지한다.

### 4.2 데스크톱 가로 분할

```text
전체 1600px
├─ Grid 1: 100px  (6.25%)
├─ Grid 2: 880px  (55%)
└─ Grid 3: 620px  (38.75%)
```

### 4.3 데스크톱 세로 분할

```text
전체 870px
├─ 상단 바: 60px  (6.89655%)
└─ 본문:    810px (93.10345%)
```

Grid 1은 상단 바와 본문을 합친 전체 높이 `870px`을 사용한다. Grid 2와 Grid 3는 상단 바 아래의 `810px` 영역에 배치한다.

### 4.4 컨테이너 상대 단위 환산

현재 홈페이지는 앱 프레임 너비를 기준으로 `cqw`를 사용한다. 기준 프레임 `1600px`에서는 다음과 같이 환산한다.

| 값 | 기준 프레임에서의 픽셀값 |
|---:|---:|
| `0.625cqw` | `10px` |
| `0.75cqw` | `12px` |
| `1cqw` | `16px` |
| `1.25cqw` | `20px` |
| `1.875cqw` | `30px` |
| `2.5cqw` | `40px` |
| `3.125cqw` | `50px` |
| `3.5cqw` | `56px` |
| `15.625cqw` | `250px` |
| `31.25cqw` | `500px` |
| `37.5cqw` | `600px` |
| `56.25cqw` | `900px` |

### 4.5 섹션별 페이지에 적용할 공통 프레임 원칙

새 섹션 페이지는 메인과 화면이 전환될 때 크기가 튀지 않도록 아래 기준에서 시작한다.

- 데스크톱 기준 뷰포트는 `1680 × 940px`이다.
- 공통 앱 프레임의 최대 기준 크기는 `1600 × 870px`이다.
- 왼쪽 내비게이션을 유지하는 경우 너비는 `100px`이다.
- 상단 공통 바를 유지하는 경우 높이는 `60px`이다.
- 내비게이션과 상단 바를 모두 유지하면 실제 섹션 콘텐츠 기준 영역은 **`1500 × 810px`**이다.
- 각 섹션의 내부 열 비율과 콘텐츠 구성은 달라질 수 있지만, 바깥 프레임·라운드·공통 메뉴 위치는 먼저 통일한다.
- 섹션 페이지 기획 단계에서 공통 프레임을 유지할지, 콘텐츠 몰입을 위해 일부 페이지에서 확장할지를 섹션별로 명시적으로 결정한다.

## 5. Grid 1 내비게이션 규격과 동작

### 데스크톱

- 전체 영역: `100 × 870px`
- 홈 및 서비스 아이콘 버튼: **`56 × 56px`**
- 서비스 아이콘 사이 간격: **`30px`**
- 기본 배경: 코랄 핑크 계열
- 기본 아이콘: 흰색 선 아이콘
- 활성 상태: 흰색 배경 + 코랄 계열 아이콘
- 홈 버튼만 별도 외곽선을 추가하지 않는다.
- 아이콘 라벨은 hover/focus/active일 때 아이콘 아래 흰색 영문으로 표시한다.

### 태블릿·모바일 (`1200px 이하`)

- 왼쪽 세로형 대신 상단 가로형 sticky 메뉴로 전환한다.
- 상단 메뉴 패딩: 위아래 `8px`, 좌우 `10px`
- 홈 및 서비스 아이콘: **`48 × 48px`**
- 아이콘 사이 간격: **`4px`**
- 아이콘은 한 줄로 유지한다.
- 공간이 부족할 때는 로고를 줄이거나 숨기고 아이콘을 두 줄로 만들지 않는다.
- 모바일 `600px 이하`에서는 상단 메뉴 로고를 숨긴다.

### 현재 메인에서의 상호작용

- 데스크톱 아이콘 hover: `140ms` 뒤 해당 섹션 미리보기를 연다.
- 아이콘 또는 카드에서 포인터가 나가면 `450ms` 뒤 미리보기를 닫는다.
- 아이콘 클릭/터치만으로 상세 페이지로 즉시 이동하지 않는다.
- 모바일 첫 터치: 해당 섹션 미리보기 표시.
- 상세 페이지 이동: 미리보기의 이동 버튼 또는 카드의 원형 화살표를 눌렀을 때만 실행.
- 미리보기 바깥을 터치하면 기본 화면으로 복귀한다.
- 키보드 `Enter`/`Space`: 미리보기 활성화.
- 키보드 `Escape`: 미리보기 닫기.

섹션 페이지에서도 공통 메뉴를 사용할 경우, 현재 페이지 아이콘은 활성 상태로 고정하고 다른 섹션 아이콘의 이동 방식은 기획 단계에서 결정해야 한다.

## 6. Grid 2 메인 장면 규격

- 데스크톱 표시 영역: **`880 × 810px`**
- 공통 배경 원본: **`1760 × 1620px`**, 비율 약 **`1.0864:1`**
- 배경 표시: `width: 100%`, `height: 100%`, `object-fit: cover`
- 메인 및 섹션 캐릭터 원본: 모두 **`1024 × 1536px`**, 비율 **`2:3`**, 투명 PNG
- 데스크톱 캐릭터 CSS 박스:
  - 왼쪽 `250px` (`15.625cqw`)
  - 위 `-60px` (`-3.75cqw`)
  - 너비 `600px` (`37.5cqw`)
  - 높이 `900px` (`56.25cqw`)
  - `object-fit: contain`
- 캐릭터 원본 자체를 크롭하거나 확대 저장하지 않는다.
- 캐릭터 간 차이는 원본 캔버스를 유지한 채 미세한 `translate` 값으로만 정렬한다.

### 현재 섹션 캐릭터 정렬 보정값

| 섹션 | X 보정 | Y 보정 | 데스크톱 추가 Y |
|---|---:|---:|---:|
| 놀자 매거진 | `+0.8%` | `+1.0%` | `-15px` |
| 프로그램 | `+1.2%` | `-0.5%` | `0px` |
| 게임 | `+0.7%` | `+1.0%` | `-15px` |
| 만들기 | `+0.4%` | `+0.8%` | `0px` |
| 웹툰 | `+0.7%` | `+0.9%` | `0px` |
| 블로그 | `-0.3%` | `+0.7%` | `0px` |

### 미리보기 상태

- 메인 캐릭터: `opacity: 0.24`, `blur(9px)`
- 선택된 섹션 캐릭터: `opacity: 1`, blur 없음
- 섹션 캐릭터에는 drop shadow만 적용한다.
- 모바일에서는 흐린 메인 캐릭터에 blur를 적용하지 않고 `opacity: 0.2`만 사용한다.
- 선택된 섹션 캐릭터가 메인 캐릭터의 blur를 상속받지 않도록 레이어를 분리한다.

### 미리보기 창

- 데스크톱 기준 너비: **`500px`**
- 데스크톱 기준 높이: **`260px`** (`clamp(238px, 16.25cqw, 284px)`)
- Grid 2 아래에서 `14%`, 즉 기준 높이에서 약 `113px` 위에 위치한다.
- 미리보기 창은 배경과 캐릭터의 blur 영향을 받지 않는 독립 레이어다.

## 7. Grid 3 서비스 카드 규격

### 영역과 배열

- Grid 3 기준 영역: **`620 × 810px`**
- 배열: **2열 × 3행**
- 순서:

```text
1 놀자 매거진 | 2 프로그램
3 게임        | 4 만들기
5 웹툰        | 6 블로그
```

- 카드 간격: **`20px`** (`1.25cqw`)
- Grid 3 데스크톱 바깥 여백:
  - 위 `16px`
  - 오른쪽 `16px`
  - 아래 `16px`
  - 왼쪽 `12px`
- Grid 3 내부 패딩:
  - 위 `20px`
  - 좌우 `20px`
  - 아래 `30px`
- 카드 모서리: **`20px`**
- Grid 3 패널 모서리: **`26px`**
- 위 수치를 적용한 `1600 × 870px` 기준에서 카드 한 칸은 서브픽셀 오차를 제외하고 약 **`265 × 229px`**이다.

### 카드 이미지 원본

- 6개 카드 이미지 원본은 모두 **`1774 × 887px`**이다.
- 원본 비율은 **`2:1`**이다.
- 투명 배경을 유지한다.
- hover 시 이미지 자체를 확대하거나 이동하지 않는다.
- 카드 껍데기만 위로 `5px` 올라가며 그림자가 강해진다.
- 이미지 위치는 데스크톱 카드의 오른쪽·아래 모서리를 기준으로 맞춘다.

### 카드별 이미지 위치값

| 섹션 | 텍스트 안전 높이 `--art-clearance` | 오른쪽 `--art-right` | 아래 `--art-bottom` |
|---|---:|---:|---:|
| 놀자 매거진 | `104px` | `12px` | `12px` |
| 프로그램 | `110px` | `-6px` | `12px` |
| 게임 | `105px` | `15px` | `10px` |
| 만들기 | `100px` | `8px` | `11px` |
| 웹툰 | `130px` | `14px` | `15px` |
| 블로그 | `120px` | `16px` | `15px` |

프로그램의 오른쪽 `-6px`은 이미지가 카드 오른쪽 밖으로 `6px` 나가도록 한 의도적인 값이다. 카드 이미지 높이는 다음 식으로 결정한다.

```css
height: calc(100% - var(--art-clearance) - var(--art-bottom));
```

### 카드 텍스트와 이동 버튼

- 카드 텍스트 영역 너비: 카드의 `72%`
- 텍스트 패딩: 위 `15px`, 오른쪽 `8px`, 아래 `10px`, 왼쪽 `15px`
- 카드 이동 버튼: **`44 × 44px`** 원형
- 버튼 위치: 카드 왼쪽 `15px`, 아래 `15px`
- 버튼 내용: 흰색 오른쪽 화살표 `→`
- 버튼은 기본 상태에서 숨긴다.
- 데스크톱 hover/focus 및 모바일 첫 터치로 카드가 활성화될 때만 표시한다.
- 화살표 버튼을 눌러야 상세 페이지로 이동한다.

## 8. 반응형 기준

### `1201px 이상`: 데스크톱

- `100 / 880 / 620px` 비율의 3그리드 앱 프레임을 유지한다.
- 상단 바 `60px`, 본문 `810px` 비율을 유지한다.
- Grid 1은 왼쪽 세로 메뉴다.
- Grid 3는 2열 × 3행이다.

### `601~1200px`: 태블릿·좁은 화면

- 앱 프레임의 고정 종횡비를 해제한다.
- 배치는 상단 메뉴 → Grid 2 → Grid 3 순서로 세로 전환한다.
- Grid 2 최소 높이: `clamp(520px, 62vw, 690px)`
- Grid 3: 2열 유지
- 카드 행 높이: `clamp(240px, 24vw, 280px)` 이상
- 공통 상단 바는 숨기고 Grid 1을 상단 sticky 메뉴로 사용한다.

### `600px 이하`: 모바일

- Grid 2 최소 높이: **`640px`**
- Grid 3: **1열 × 6행**
- 카드 높이: **`240px`**
- 메인 및 섹션 캐릭터:
  - `left: 64%`
  - `top: 20%`
  - `height: 80%`
- 미리보기 최대 너비: `340px`, 화면 너비의 `84%` 이하
- 상단 메뉴 로고는 숨긴다.
- 카드의 첫 터치는 미리보기와 원형 화살표를 표시하고, 두 번째 행동은 화살표를 눌러 이동하는 방식이다.

### 모바일 가로형

- `1200px 이하 + landscape`: 캐릭터 `left: 48%`
- `1201px 이상 + landscape + 높이 700px 이하`: 캐릭터 `left: 11cqw`
- 이미지 크기나 원본 캔버스를 바꾸지 않고 좌우 위치만 보정한다.

## 9. 공통 UI 스타일

### 핵심 인상

```text
Clean + Warm + Editorial + Character/IP
```

- 유아용 장난감 사이트처럼 지나치게 알록달록하게 만들지 않는다.
- 교사가 오래 사용해도 피로하지 않은 낮은 정보 밀도와 넓은 여백을 사용한다.
- 카드와 창은 독립적인 둥근 패널로 구성한다.
- 그림자는 약하고 부드럽게 사용한다.
- 손그림 요소는 보조 장식으로만 사용하고 기능과 정보보다 앞서지 않게 한다.

### 공통 브랜드 색상

| 용도 | 색상 |
|---|---|
| Seashell / 따뜻한 기본 면 | `#FAF0EA` |
| Old Rose / 주요 따뜻한 강조 | `#E19AA6` |
| Sky Blue / 차가운 강조·링크 | `#82B0CE` |
| 기본 본문 | `#2E2E2E` |
| 보조 본문 | `#7E7872` |
| 선·테두리 | `#E8DDD5` |

### 글꼴

- 제품 UI·본문·내비게이션: **Pretendard**
- 캐릭터 대사·말풍선: **Poor Story**
- 손글씨 메모·강조: **Nanum Pen Script**
- 영문 UI 보조: **Manrope**
- 손글씨 글꼴은 포인트에만 사용하며 일반 본문에 사용하지 않는다.

## 10. 에셋과 제작 제약

### 현재 사용하는 원본 규격

| 구분 | 규격 | 형식·비고 |
|---|---:|---|
| Grid 2 배경 | `1760 × 1620px` | 공통 배경 |
| 메인 캐릭터 | `1024 × 1536px` | 투명 PNG |
| 섹션 캐릭터 6종 | 각 `1024 × 1536px` | 투명 PNG, 동일 캔버스 |
| 카드 이미지 6종 | 각 `1774 × 887px` | 투명 PNG, 2:1 |
| Direction 1 로고 | `1748 × 637px` | PNG, 약 2.744:1 |

### 절대 지켜야 할 규칙

- 메인 캐릭터 이미지는 수정하지 않는다.
- 섹션 캐릭터 이미지를 임의로 크롭하거나 확대 저장하지 않는다.
- 캐릭터의 머리·손·다리·발이 원본 단계에서 잘리지 않게 한다.
- 모든 섹션 캐릭터는 `1024 × 1536px` 동일 캔버스에서 제작한다.
- 캐릭터 비율은 눈 위치부터 이미지 하단까지의 픽셀 길이를 비교해 맞춘다.
- 캐릭터 좌우 정렬도 얼굴·눈 중심과 몸의 중심축을 이미지 분석하여 맞춘다.
- 허용되는 차이는 CSS의 소규모 `translate` 값으로만 보정한다.
- 카드 이미지 원본은 `1774 × 887px` 투명 캔버스를 유지한다.
- 카드 hover에서 이미지가 확대되거나 위치가 바뀌면 안 된다.
- 현재 실제 페이지에서 사용하지 않는 레퍼런스는 로컬 `sample/` 폴더에 보관한다.
- `sample/`은 Git에 푸시하지 않는다.
- 운영 코드에서 `sample/` 파일을 참조하지 않는다.

## 11. 섹션별 시각 방향의 현재 기준

| 섹션 | 화면 성격 | 캐릭터·대표 이미지 방향 |
|---|---|---|
| 놀자 매거진 | 에디토리얼·주간 놀이 큐레이션 | 계절감, 잡지, 놀이·교육 비주얼 |
| 프로그램 | 교사용 생산성 도구 | 사각 뿔테 안경, 짧은 청바지, 핑크 밴드 스마트워치, 노트북 |

## 12. 섹션 페이지 기획에서 결정해야 할 항목

일반 채팅에서는 아래 항목을 섹션별로 하나씩 확정한다.

### A. 공통 셸

1. 섹션 페이지에서도 `1600 × 870px` 앱 프레임을 그대로 유지할지
2. 왼쪽 `100px` Grid 1을 유지할지
3. 상단 `60px` 로고 바를 유지할지
4. 현재 섹션 아이콘의 활성 표시 방식
5. 다른 섹션으로 이동할 때 미리보기를 거칠지 바로 이동할지

### B. 섹션별 첫 화면

각 섹션마다 다음을 정한다.

- 페이지의 한 문장 목적
- 사용자가 가장 먼저 해야 하는 행동 1개
- 첫 화면에 반드시 보여야 하는 콘텐츠
- 첫 화면에서 숨겨도 되는 보조 콘텐츠
- 캐릭터가 기능을 안내하는지, 브랜드 비주얼로만 존재하는지
- 목록형·에디토리얼형·작업공간형 중 어떤 구조인지

### C. 콘텐츠 구조

- 고정 메뉴와 카테고리
- 검색 필요 여부
- 정렬·필터 필요 여부
- 상세 페이지 또는 작업 화면의 단계
- 실제 콘텐츠가 없을 때의 빈 상태
- 로그인·저장·다운로드 등 사용자 상태가 필요한 기능

### D. 반응형 구조

- 데스크톱 `1680 × 940px`
- 노트북 및 좁은 데스크톱
- 태블릿 `601~1200px`
- 모바일 `600px 이하`
- 모바일 가로형 및 브라우저 상·하단 UI가 보이는 실제 높이

### E. 필요한 에셋

- 대표 캐릭터 사용 여부
- 배경 이미지 필요 여부
- 썸네일·표지·게임 화면·템플릿·웹툰 컷 등 실제 콘텐츠 이미지 목록
- 각 이미지의 캔버스 규격과 투명 배경 여부
- 임시 이미지와 최종 이미지의 구분

## 13. 권장 기획 순서

모든 페이지를 동시에 상세 기획하지 않고 아래 순서로 진행한다.

1. **공통 셸 확정** — 프레임, 내비게이션, 상단 바, 모바일 메뉴
2. **프로그램 페이지** — 실제 도구 중심의 가장 기능적인 페이지
3. **놀자 매거진** — 에디토리얼 콘텐츠 구조 확정
4. **게임** — 실제 게임이 없을 때의 진입·목록 구조 확정
5. **만들기** — 템플릿 선택과 결과물 제작 흐름 확정
6. **웹툰** — 작품·회차·캐릭터 탐색 구조 확정
7. **블로그** — 글 목록·카테고리·상세 구조 확정
8. 각 페이지별 모바일 구조 확정
9. 확정 내용을 구현용 Markdown으로 다시 정리한 뒤 Codex에서 제작

- ...

## 태블릿 정보 구조
- ...

## 모바일 정보 구조
- ...

## 인터랙션
- ...

## 필요한 콘텐츠와 에셋

- 규격:
