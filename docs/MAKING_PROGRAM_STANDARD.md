# Kinder Edu 만들기 프로그램 제작·연동 기준

> 문서 상태: 만들기 섹션 독립 프로그램 공통 기준<br>
> 적용 범위: `KINDER-EDU-PROJECT\SECTION-CREATE` 아래에서 새로 만드는 모든 프로그램<br>
> 홈페이지 연결 대상: `WEB-WEBSITE/create.html`의 중앙 실행창<br>
> 개인정보 원칙: 학급 정보와 학급원 이미지는 사용자 브라우저 안에서만 관리한다.

---

## 1. 기본 구조

만들기 프로그램은 모두 홈페이지와 분리된 독립 프로젝트로 만든다.

```text
KINDER-EDU-PROJECT/
├─ WEB-WEBSITE/                 # Kinder Edu 홈페이지
│  └─ create.html              # 만들기 섹션 호스트
└─ SECTION-CREATE/
   ├─ <making-tool-a>/         # 독립 프로젝트·Git 저장소·배포
   ├─ <making-tool-b>/
   └─ <making-tool-c>/
```

필수 원칙:

- 프로그램마다 별도 폴더, 별도 Git 저장소, 별도 Vercel 프로젝트를 사용한다.
- `WEB-WEBSITE` 안에 독립 프로그램의 소스나 빌드 결과를 복사하지 않는다.
- 홈페이지는 실행창과 학급 자료를 제공하고, 실제 제작 기능은 독립 프로그램이 담당한다.
- 프로그램 저장소에서 홈페이지의 `index.html`, 다른 섹션 HTML, 공통 CSS·JS를 수정하지 않는다.
- 홈페이지 연결 변경은 만들기 섹션 담당 작업에서만 수행한다.

---

## 2. 홈페이지 레이아웃 책임

만들기 섹션은 프로그램 섹션과 동일한 열 규격을 사용한다.

| 영역 | 기준 너비 | 책임 |
|---|---:|---|
| 왼쪽 | `220px` | 통일된 아이콘과 이름으로 만들기 프로그램을 선택한다. |
| 중앙 | `1012px` | 첫 진입에는 시작 안내, 프로그램 선택 후에는 해당 프로그램을 표시한다. |
| 오른쪽 | `320px` | 학급 선택, 학급원 선택, 이미지 등록과 백업을 담당한다. |

메인 영역의 기준 높이는 `692px`이다. 데스크톱 기준 중앙 실행 영역은 **`1012 × 692px`**이다.

홈페이지가 담당하는 항목:

- 공통 상단 내비게이션
- 공통 하단 푸터
- 중앙 프로그램 실행 컨테이너
- 우측 학급 관리
- 학급·학급원 자료의 IndexedDB 저장
- 독립 프로그램과의 데이터 전달

독립 프로그램은 홈페이지의 메뉴, 푸터, 학급 관리 UI를 중복해서 만들지 않는다.

### 2.1 첫 진입과 프로그램 선택

- 만들기 섹션을 처음 열거나 새로고침하면 아무 프로그램도 자동 실행하지 않는다.
- 직전에 실행했던 프로그램을 저장하거나 자동 복원하지 않는다.
- 첫 중앙 화면에는 **좌측에서 프로그램 선택**, **우측에서 학급 입력** 안내를 표시한다.
- 학급 또는 학급원을 등록·선택하는 것만으로 프로그램이 열리지 않는다.
- 프로그램은 좌측 항목의 클릭 또는 키보드 실행으로만 중앙에 열린다.
- 프로그램 파일과 모델은 해당 프로그램을 선택한 뒤 불러온다.
- 좌측의 `시작 안내` 버튼으로 안내 화면에 돌아갈 수 있다.
- 실행 중 학급을 변경하면 선택한 프로그램에 새 자료를 반영한다.
- 얼굴쏙은 별도 `SECTION-CREATE/face-ssok` 저장소와 Vercel 프로젝트에서 관리한다. 홈페이지의 `making-face-ssok-bridge.js`는 런처용 `FaceSsok.mount/update/selectPerson` 인터페이스를 유지하되 실제 편집기는 iframe으로 불러오고 아래 메시지 규약으로 선택 자료만 전달한다. 편집 소스·모델·도안은 홈페이지 저장소에 복사하지 않는다.

### 2.2 만들기 아이콘 공통 규격

- 원본은 `64 × 64` viewBox의 SVG로 만든다.
- 배경은 `58 × 58`, 좌표 `(3, 3)`, 모서리 반경 `17px`로 통일한다.
- 선 두께 `2px`, 둥근 끝과 둥근 연결을 사용한다.
- 배경 `#FAF0EA`, 선 `#52758B`, 보조색 `#82B0CE`와 `#E19AA6`를 사용한다.
- 그림자·그라데이션·이모지·이미지 안의 글자는 사용하지 않는다.
- 좌측 프로그램 아이콘은 `44 × 44px`로 표시하고 이름은 HTML 텍스트로 배치한다.
- 파일은 `assets/making/icons/<program-id>.svg`에 저장한다.
- 얼굴 쏙 아이콘 `face-ssok.svg`를 후속 프로그램 아이콘의 기준으로 삼는다. 안내 아이콘도 같은 선과 팔레트를 사용한다.

## 3. 중앙 실행창 규격

모든 만들기 프로그램은 `1012 × 692px` 논리 화면에서 핵심 기능이 완성되어야 한다.

### 필수 규격

- 기준 크기: `1012 × 692px`
- 페이지 바깥 여백: `0`
- 프로그램 내부 기본 여백: `16px`
- 독립 패널 사이 간격: `12px`
- 화면 전체에 가로 스크롤을 만들지 않는다.
- 첫 화면에서 핵심 제작 기능과 주요 실행 버튼이 보여야 한다.
- 홈페이지가 외곽 패널, 라운드와 그림자를 담당하므로 앱 최외곽에 이중 카드나 큰 그림자를 만들지 않는다.
- iframe 안의 `html`, `body`, 앱 루트는 너비와 높이 `100%`를 사용한다.
- 데스크톱 임베드 화면에서는 `body` 스크롤보다 앱 내부의 필요한 영역만 스크롤한다.

권장 CSS 기준:

```css
html,
body,
#app {
  width: 100%;
  height: 100%;
  margin: 0;
}

* {
  box-sizing: border-box;
}

body.is-kinder-embedded {
  overflow: hidden;
  background: transparent;
}
```

### 작은 화면

- `1200px` 이하에서는 홈페이지가 열을 세로로 재배치할 수 있다.
- 프로그램은 중앙 영역의 실제 크기를 기준으로 반응형 처리한다.
- 최소 검증 폭은 `820px`, `600px`, `390px`이다.
- `390px`에서 문서 전체의 가로 넘침이 없어야 한다.
- 고정 픽셀 축소만으로 글자가 읽기 어려워지면 도구 패널을 접거나 세로 배치한다.

## 4. 임베드 모드

독립 프로그램은 단독 실행과 Kinder Edu 임베드 실행을 모두 지원한다.

권장 주소:

```text
https://<project>.vercel.app/?embed=kinder-edu
```

임베드 모드 판별 예시:

```js
const isKinderEmbedded =
  window.self !== window.top ||
  new URLSearchParams(window.location.search).get('embed') === 'kinder-edu';

document.body.classList.toggle('is-kinder-embedded', isKinderEmbedded);
```

임베드 모드에서는 다음을 숨긴다.

- 독립 사이트용 상단 메뉴와 로고
- 독립 사이트용 푸터
- 홈페이지와 중복되는 제목·소개 화면
- 학급 생성·수정·이미지 등록 UI
- 불필요한 바깥 여백과 배경 장식

임베드 모드에서도 프로그램의 제작 도구, 미리보기, 다운로드 기능은 그대로 동작해야 한다.

---

## 5. 학급 자료 소유권

학급 자료의 원본은 항상 홈페이지 만들기 섹션이 소유한다.

- 저장 위치: 홈페이지 origin의 IndexedDB
- 저장 주체: `create.html`의 학급 관리 기능
- 프로그램이 IndexedDB를 직접 열거나 수정하지 않는다.
- 프로그램별 서버나 외부 API에 학급 자료를 업로드하지 않는다.
- 프로그램은 현재 작업에 필요한 선택 자료만 메모리에서 사용한다.
- 프로그램을 닫거나 새로고침하면 전달받은 자료를 영구 보관하지 않는다.
- 프로그램에서 학급 정보를 수정하는 기능을 만들지 않는다.

사용자가 만드는 결과물은 브라우저에서 생성하여 사용자 컴퓨터로 다운로드한다. 서버 저장이 필요한 기능은 별도 개인정보 검토와 명시적인 사용자 결정 전에는 구현하지 않는다.

## 6. 학급 자료 전달 규약

부모 페이지와 iframe은 `postMessage`를 사용한다. `targetOrigin`에 `*`를 사용하지 않는다.

### 6.1 프로그램 준비 신호

프로그램이 초기화를 마치면 부모 페이지에 준비 신호를 보낸다.

```js
window.parent.postMessage(
  {
    type: 'KINDER_MAKING_READY',
    version: 1,
    toolId: 'example-tool'
  },
  'https://kinder-edu.vercel.app'
);
```

로컬 개발 주소는 명시적인 허용 목록으로 따로 관리한다. 운영 코드에서 모든 origin을 허용하지 않는다.

### 6.2 홈페이지가 보내는 자료

```js
{
  type: 'KINDER_MAKING_CLASS',
  version: 1,
  toolId: 'example-tool',
  classInfo: {
    year: '2026',
    className: '햇살반',
    ageGroup: '만 4세',
    institution: '',
    teacherName: ''
  },
  children: [
    {
      id: 'local-child-id',
      num: 1,
      name: '김하준',
      birth: '',
      image: 'data:image/webp;base64,...'
    }
  ],
  sentAt: '2026-10-15T00:00:00.000Z'
}
```

전달 규칙:

- 사용자가 우측 패널에서 선택한 학급원만 보낸다.
- 프로그램이 요구하지 않는 필드는 보내지 않는다.
- `birth`는 생일 관련 프로그램에서만 요청한다.
- `institution`, `teacherName`은 결과물에 실제로 쓰는 프로그램에서만 요청한다.
- 이미지는 로컬에서 정규화한 JPG·PNG·WebP 데이터만 사용한다.
- 원본 이미지 파일명, 로컬 경로, EXIF 정보는 전달하지 않는다.
- 각 프로그램은 `toolId`와 `version`을 확인한 후 자료를 적용한다.

### 6.3 프로그램 수신 검증

```js
const allowedParents = new Set([
  'https://kinder-edu.vercel.app',
  'http://127.0.0.1:8126'
]);

window.addEventListener('message', event => {
  if (!allowedParents.has(event.origin)) return;
  const payload = event.data;
  if (!payload || payload.type !== 'KINDER_MAKING_CLASS') return;
  if (payload.version !== 1 || payload.toolId !== 'example-tool') return;
  if (!Array.isArray(payload.children)) return;

  // 필드 길이, 인원 수, 이미지 형식을 다시 검증한 뒤 메모리에만 보관한다.
});
```

프로그램은 부모가 보낸 문자열을 `innerHTML`에 직접 넣지 않는다. 화면에는 `textContent` 또는 프레임워크의 안전한 텍스트 바인딩을 사용한다.

## 7. 프로그램 요구사항 선언

각 독립 프로그램은 저장소 루트에 `making-tool.json`을 둔다.

```json
{
  "schemaVersion": 1,
  "id": "example-tool",
  "name": "예시 만들기",
  "description": "우리 반 자료로 예시 결과물을 만듭니다.",
  "entry": "https://example-tool.vercel.app/?embed=kinder-edu",
  "selectionMode": "multiple",
  "classFields": ["year", "className"],
  "childFields": ["num", "name", "image"],
  "outputFormats": ["png", "pdf"],
  "dataPolicy": "memory-only"
}
```

허용값:

| 항목 | 값 |
|---|---|
| `selectionMode` | `single`, `multiple`, `all` |
| `classFields` | `year`, `className`, `ageGroup`, `institution`, `teacherName` |
| `childFields` | `num`, `name`, `birth`, `image` |
| `outputFormats` | 프로그램이 실제 제공하는 형식만 기재 |
| `dataPolicy` | 현재는 `memory-only`만 허용 |

홈페이지에 프로그램을 연결할 때 이 선언과 실제 동작이 일치하는지 확인한다.

## 8. 디자인 기준

- Kinder Edu의 만들기 색상과 공통 디자인 언어를 따른다.
- 기본 만들기 Accent: `#7DBB91`
- Hover Accent: `#63A879`
- Soft Surface: `#ECF5EE`
- 기본 텍스트: `#2E2E2E`
- 보조 텍스트: `#7E7872`
- 선 색상: `#E8DDD5`
- 과도한 무지개색, 장난감 같은 장식, 강한 그림자와 과도한 애니메이션을 피한다.
- 버튼명과 안내 문구는 교사가 한 번에 이해할 수 있는 한국어를 사용한다.
- 이미지에 제목과 설명을 합성하지 않고 UI 텍스트로 제공한다.

프로그램의 개성은 작업물과 도구 구성에서 표현하되, 기본 여백·버튼 높이·패널 라운드·텍스트 위계는 Kinder Edu와 어울리게 유지한다.

## 9. 출력과 다운로드

- 결과물은 브라우저에서 생성한다.
- 다운로드 전에 미리보기와 대상 학급원 수를 보여준다.
- 단일 결과와 일괄 결과를 명확히 구분한다.
- 여러 결과는 ZIP 또는 프로그램에 적합한 묶음 형식으로 제공한다.
- 파일명에는 학급명이나 학급원 이름을 사용할 수 있으나 운영체제에서 허용하지 않는 문자는 제거한다.
- 다운로드 성공 여부를 사용자에게 표시한다.
- 인쇄 기능은 A4 또는 실제 출력 규격과 배율을 문서화하고, 인쇄 미리보기에서 잘림을 확인한다.

---

## 10. 접근성과 상태 처리

- 모든 버튼은 키보드로 조작할 수 있어야 한다.
- 입력 요소에는 보이는 라벨 또는 `aria-label`을 제공한다.
- 선택 상태는 색상 외에도 테두리, 체크, 텍스트 등으로 구분한다.
- 이미지가 없어도 기본 아바타로 전체 기능을 사용할 수 있어야 한다.
- 학급 또는 학급원이 선택되지 않은 상태를 정상적인 빈 상태로 처리한다.
- 프로그램 로딩 실패, 자료 전달 실패, 출력 실패에는 다음 행동을 알 수 있는 한국어 안내를 제공한다.
- 저장되지 않은 편집 내용이 있을 때 페이지 이탈로 작업이 사라질 수 있으면 경고한다.

---

## 11. 금지 사항

- 학급 정보나 이미지를 서버로 전송하는 기능
- 분석, 오류 보고, 로그에 학급원 이름이나 이미지 데이터를 포함하는 기능
- `localStorage`, IndexedDB 또는 쿠키에 전달받은 학급 자료를 프로그램이 다시 저장하는 기능
- 부모 페이지의 DOM이나 IndexedDB를 iframe에서 직접 조작하는 기능
- `postMessage`의 origin 검증을 생략하는 구현
- `targetOrigin: '*'` 사용
- 실제로 존재하지 않는 프로그램을 홈페이지에 등록하는 행위. 로컬에서 개발 중인 프로그램은 실제 소스에 연결하고, 연결 실패 안내를 제공하며 배포 완료로 표시하지 않는다.
- 첫 진입·새로고침·학급 변경만으로 프로그램을 자동 실행하는 행위
- 다른 섹션이나 홈페이지 전체를 프로그램 저장소에서 수정·배포하는 행위
